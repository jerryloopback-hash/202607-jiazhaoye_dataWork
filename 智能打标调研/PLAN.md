## 阶段 1 · 数据库结构了解（基于 schema/注释 ✅ 已通读）

**方法**：以 `ods_wenti_starrocks.sql` 表名/字段/注释为唯一依据；本阶段不连库校验质量。

**结构认知（✅）**：三套源系统，带 `extract_time`。

| 源 | 前缀 | 典型表 | 定位 |
|---|---|---|---|
| 一起吗（C端） | `..._jianengliang_` | `j_member`、`j_member_order(_detail/_refund)`、`j_platform_activity(_person)`、`j_points_records`、`j_coupon*`、`j_order_ticket`、`j_time_card*` | 移动端用户、全品类订单、活动、积分、优惠券、游泳票、次卡 |
| 场馆（B端） | `..._vmdb_` | `h_member`、`h_member_card*`、`m_trade_order(_detail/_pay/_refund)`、`m_enter_gate`、`m_group_ticket*`、`theatre_ticket*`、`p_park_record` | 线下场馆会员、储值卡、交易、入闸、票类、剧场、停车 |
| 培训 | `..._training_` | `t_student`、`m_trade_order(_course/_detail)`、`t_student_check`、`t_syllabus_student`、`t_class(_teacher)` | 培训学员、报课、消课、考勤 |

**场景分派的数据依据（按注释推断）：**
- **场景 A（DWS 直算）**：用户主实体（`j_member` 优先或跨源合并）× 行为聚合（订单/票类/活动/积分/次卡）→ 用户×特征宽表 → 聚类。
- **场景 B（DWS 直算预测）**：用户 × 行为聚合（订单/游泳票/活动/积分/次卡）→ 观察窗特征 + 标签窗自造 y → **XGBoost 流失预测**（不需 ER）。

**已识别口径坑**：性别三套枚举不一致；`status/order_status/pay_status` 同名异义；用户主体三表跨源（`j_member`/`h_member`/`t_student`）。

## 阶段 2 · 方法调研（✅ 初版调研，部分待补）

**判定基调**：标签分 统计/规则/模型/算法（或 事实/模型/预测），仅"模型/算法/预测"类为本项目对象。

**方法库（本项目可选）**

| 大类 | 算法/技术 | 产出的标签 | 对应场景 |
|---|---|---|---|
| A. 无监督聚类 | K-means/GMM/DBSCAN/模糊C；PCA/UMAP | 用户分群/偏好簇 | **场景 A（首选）** |
| B. 监督/预测 | LR/RF/GBDT/XGB | 概率标签（复购/流失/高潜） | **场景 B（首选，XGBoost 流失预测，DWS 直算）** |
| C. 嵌入/表征 | item2vec / node2vec（图嵌入）/ doc2vec | 偏好向量、相似人群、兴趣类群 | 可扩展（本期不采用场景 B） |
| D. 深度序列/深度聚类 | LSTM/GRU/Transformer；DEC | 序列行为画像 | 可扩展 |
| E. 综合 | 多标签、RFM+聚类、嵌入+聚类 | 一人多标签、可解释分群 | 可扩展 |

**工程范式**：特征宽表 → 小数据无标注先聚类 → 有监督信号上预测 → 有序列/关系上嵌入 → 轮廓系数/降维可视化/抽样复核。

**待办**：补采多标签学习、对比学习在画像的应用、离线批量打瞻与特征管线做法。

## 阶段 3 · 两个场景与标签需求构建

**目标**：场景 A（DWS 直算聚类）与场景 B（DWS 直算预测），各定一个业务场景 + 一个标签 + 一种智能方法。

### 候选（已与用户确认锁定）

| | 场景 A（DWS 直算） | 场景 B（DWS 直算预测） |
|---|---|---|
| 业务场景 | C 端用户**消费行为分群**（用 `j_member` × 订单/票/活动/积分聚合） | C 端用户**流失预警**（观察窗行为 → 预测未来 30 天是否流失） |
| 标签 | 「行为偏好簇」：高频游泳型 / 周末订场型 / 活动热衷型 / 沉睡型 | 「流失概率/等级」：高危流失 / 中危流失 / 低危-稳定 |
| 标签类型 | 行为/属性类（DWS 直算） | 概率/预测类（DWS 直算，自造 y） |
| 智能方法 | **无监督聚类**（K-means/GMM，PCA/UMAP 可视化） | **有监督预测**（XGBoost，观察窗特征→标签窗 y，防泄漏切分） |
| 是否需真实标签 | 否（无监督） | 否（自造 y：观察期→标签期是否流失） |
| 主要数据表 | `j_member`、`j_member_order`、`j_order_ticket(_valid)`、`j_platform_activity_person`、`j_points_records` | 同 A（C 端行为表），另含 `j_time_card_use` |

### 敲定标准
1. 有业务价值；2. 智能方法必要性显著（隐性、多因素、无直接字典）；
3. 依据 schema/注释判断数据支撑（字段、关系、时间维度可行）；
4. 两场景一聚类一预测（无监督 + 有监督）互补对照。

**（场景 B 原规划为图嵌入/ER 关系，2026-08-31 调整为 XGBoost 预测、DWS 直算。）**

交付见：`03_场景与标签需求/场景标签与方法匹配.md`、`04_方案设计与实施/场景A/B_方案设计与打标模拟.md`。

## 阶段 4 · 两套方案设计与实施

### 4.1 方案设计（以 schema/注释为准）
- **特征工程**：场景 A 做「用户 × 行为窗口指标」宽表 + 聚类；场景 B 做「观察窗特征 + 标签窗自造 y」（严格切观察期/标签期防泄漏），统一口径坑（性别/状态码/跨源主体）。
- **算法选型**：A=无监督聚类；B=**有监督预测 XGBoost**（观察窗→标签窗，自造流失 y）。
- **评估**：A→轮廓系数/簇画像；B→AUC/PR-AUC/混淆矩阵/特征重要性。

### 4.2 实施（链路演示；测试库质量差 → 用合成数据 + LLM 增强模拟生产质量）
- 场景 A：连测试库或合成数据 → 特征 → 聚类 → 标签 → 可视化。
- 场景 B：**ODS 改造(SQL) → 特征宽表(合成数据/脚本) → 自造标签 → XGBoost 训练/评估 → 批量打标 → 增量重训(版本化)**。
- 测试质量差属预期：只说明链路可运行、方法可行性/受限点。

### 4.3 总结
`05_总结/项目总结报告.md`：方法库回顾、两场景落地效果对比、局限、生产化建议（ODS 改造/特征管线/离线调度/标签存储/增量重训）。

## 风险与注意事项

- 测试数据质量差：不以之评判标签；方案按 schema+生产假设。
- 无真实标注：场景 A 无监督聚类、场景 B 自造标签窗 y，避免幻觉式评估。
- 数据模拟：场景 B 用合成数据(脚本)+LLM 增强跑通链路；生产化需替换为生产 DWS 宽表/ODS。
- 隐私字段：仅内部 join，产物脱敏。

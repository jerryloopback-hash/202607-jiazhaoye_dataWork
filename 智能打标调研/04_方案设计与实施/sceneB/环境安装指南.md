## 1. Python 环境安装（已验证步骤）

### 1.1 创建独立虚拟环境并安装依赖

```bash
cd 智能打标调研/04_方案设计与实施/sceneB
python3 -m venv .venv                # Python ≥ 3.10 即可（本机 3.14.4 验证通过）
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

`requirements.txt` 为本机实测通过版本：

| 包 | 版本 | 说明 |
|---|---|---|
| numpy | 2.5.2 | 数值计算 |
| pandas | 3.0.5 | 读特征宽表 CSV |
| scikit-learn | 1.9.0 | 评估指标（AUC/PR-AUC/混淆矩阵/分类报告） |
| xgboost | 3.4.1 | 训练/预测（CPU 版即可，**无需 GPU**） |

> pip 会附带安装 nvidia-nccl 等传递依赖，属 xgboost 正常依赖，机器无 GPU 不影响运行。

### 1.2 资源要求

- **无需 GPU**；12k 用户×15 特征训练在 CPU 上秒级完成。
- 内存：demo 级（<10 万样本）8GB 足够；生产百万用户级建议 32GB+（与 [硬件资源调研](../../02_方法调研/硬件资源与CDP调研.md) 口径一致）。
- 磁盘：模型文件每个 ~200KB，版本化保留历史占用可忽略；特征宽表 CSV 按百万用户 ~100MB/期估。

### 1.3 安装验证

```bash
.venv/bin/python -c "import numpy,pandas,sklearn,xgboost; print('OK', xgboost.__version__)"
```

### 1.4 无外网服务器的离线安装

```bash
# 在有外网的同架构机器上下载 wheel 包：
.venv/bin/pip download -r requirements.txt -d wheels/
# 拷贝 wheels/ 到服务器后离线安装：
.venv/bin/pip install --no-index --find-links=wheels/ -r requirements.txt
```

## 2. 本地 LLM 接入（已联通，2026-09-01 实测）

配置文件：`config/llm_config.json`（`enabled=true`，脚本自动读取）。

| 项 | 值 |
|---|---|
| base_url | `http://10.20.77.89:8888/v1`（OpenAI 兼容协议） |
| model | `Qwen3.8-27B-UD-Q8_K_XL`（即 qwen3.8；以 `/v1/models` 返回的 id 为准） |
| api_key | 见配置文件（unsloth 服务 key） |

### ⚠️ 该服务器（Unsloth Studio）的特殊行为

- **模型默认不驻留内存**：`/v1/models` 显示 `"loaded": false`。直接调 `/v1/chat/completions` 会**长时间挂起无响应**。
- **先加载模型**（二选一）：
  1. API：`curl -X POST -H "Authorization: Bearer <key>" -H "Content-Type: application/json" -d '{"model_path":"Qwen3.8-27B-UD-Q8_K_XL"}' http://10.20.77.89:8888/v1/load`；
  2. 网页端：Settings → API → 开启 **Model auto-switch**，让 `/v1` 请求自动加载模型。
- 加载完成判据：`GET /v1/models/<id>` 返回 `"loaded": true`。

### 📌 2026-09-01 实测加载记录（重要）

- 连通性正常：`/v1/models` 秒回 200；但 `POST /v1/load` 持有连接 **超过 30 分钟仍未完成**，期间 `/v1/models` 始终 `"loaded": false`（部分请求超时无响应，服务端疑似被加载过程占住）。
- **判断**：qwen3.8 为 27B 的 Q8 量化（权重约 30GB，加 KV cache 需 40GB+ 空闲内存），当前大概率是**服务器空闲内存不足或磁盘过慢**导致加载无法完成；客户端断开（curl 超时）后加载可能被取消/重启。
- **建议（按优先级）**：
  1. 在服务器网页端 Settings → API 开启 **Model auto-switch**（最省事，按需自动加载）；
  2. 检查服务器空闲内存（`free -h`）是否 ≥ 40GB，不足则关闭其他占用或加大内存/swap；
  3. 若内存确实不够，改用更小量化版本（如 Q4_K_M，约 16GB）并在 `config/llm_config.json` 同步更新 `model` id；
  4. 加载成功后再运行 `scripts/sceneB_llm_augment.py`（脚本带 mock 回退，模型未就绪时每条样本会等待 timeout 后回退，**不要在加载未完成时跑大 frac**）。
- **回退保障**：模型不可用时（无加载在途）chat 接口快速返回 400，`sceneB_llm_augment.py` 会逐样本秒级回退 mock 并打 `[llm失败回退: HTTPError]` 标记，管线不中断——2026-09-01 即以此方式产出了 15 维 schema 的 `features_augmented.csv`（来源标记为 mock，待模型就绪后重跑即可获得 LLM 真实判定）。

### 联通自检

```bash
# 1) 列模型（应返回 200 与模型列表）
curl -H "Authorization: Bearer <key>" http://10.20.77.89:8888/v1/models
# 2) 一次真实对话（先确保已加载）
curl -H "Authorization: Bearer <key>" -H "Content-Type: application/json" \
  -d '{"model":"Qwen3.8-27B-UD-Q8_K_XL","messages":[{"role":"user","content":"回复OK"}],"max_tokens":10}' \
  http://10.20.77.89:8888/v1/chat/completions
```

> 脚本侧已做的适配：`llm_judge` 会容忍模型输出中的 `<think>...</think>` 推理段与 ``` 代码块包裹后输出纯 JSON；`max_tokens`、判定样本比例 `frac` 均可在配置里调（当前 frac=0.05，即 600 样本做 LLM 二次判定，其余走确定性 mock）。

## 3. 全链路运行（本机已跑通）

```bash
cd 智能打标调研/04_方案设计与实施/sceneB
.venv/bin/python scripts/sceneB_synth_data.py      # ① 合成 ODS 数据（纯stdlib，可跳过若已有）
.venv/bin/python scripts/sceneB_featurize.py       # ② 特征宽表15维 + 自造标签 + 切分
.venv/bin/python scripts/sceneB_llm_augment.py     # ③（可选）LLM 增强（需模型已加载）
.venv/bin/python scripts/sceneB_model_router.py    # ④ 训练+评估+全量打标（默认 xgboost）
# 路由参数：--model {xgboost,lr,rf,rule} 选方法；--compare 四方法同台对比；--mode predict 日常打标
```

**2026-09-01 实测结果**（版本 `xgboost_20260901_144225`）：
AUC=0.7134，PR-AUC=0.6901，测试集真实流失率 47.5%；
**四方法同台对比**：随机森林 0.7215 / XGBoost 0.7134 / 逻辑回归 0.7084 / RFM规则评分卡 0.7044（机器学习整体优于传统规则）；
全量 12000 用户打标分布：高危流失 24.0% / 中危流失 37.3% / 低危-稳定 38.7%；
Top 特征：`n_events_30d`(0.295) > `n_events` > `recency_days`（近30天行为是流失最强信号，符合业务直觉）。

## 4. 版本兼容说明（踩坑记录）

- **xgboost ≥ 2.0**：移除了 `use_label_encoder`；`early_stopping_rounds`/`eval_metric` 从 `fit()` 移到构造器。`sceneB_model_router.py` 已做**版本自适应**（用 `inspect` 探测参数位置），1.x 与 3.x 均可运行。
- **scale_pos_weight 方向**：应为 负样本数/正样本数 = `(1-y.mean())/y.mean()`（上权重少数的流失类）；初版写成反了，已修正。
- pandas 3.x / numpy 2.x 与脚本兼容，未发现问题。

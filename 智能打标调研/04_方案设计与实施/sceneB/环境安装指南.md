### ⚠️ 该服务器（Unsloth Studio）的特殊行为

- **模型默认不驻留内存**：`/v1/models` 显示 `"loaded": false`。直接调 `/v1/chat/completions` 会**长时间挂起无响应**。
- **先加载模型**（二选一）：
  1. API：`curl -X POST -H "Authorization: Bearer <key>" -H "Content-Type: application/json" -d '{"model_path":"Qwen3.8-27B-UD-Q8_K_XL"}' http://10.20.77.89:8888/v1/load`；
  2. 网页端：Settings → API → 开启 **Model auto-switch**，让 `/v1` 请求自动加载模型。
- 加载完成判据：`GET /v1/models/<id>` 返回 `"loaded": true`。

### 📌 2026-09-01 实测加载记录（历史问题，✅ 2026-09-02 已解决）

> **2026-09-02 更新**：用户调试后端点已可用（直连即回、无需手动 /v1/load），
> 下方排查记录留档备查。

- 连通性正常：`/v1/models` 秒回 200；但 `POST /v1/load` 持有连接 **超过 30 分钟仍未完成**，期间 `/v1/models` 始终 `"loaded": false`（部分请求超时无响应，服务端疑似被加载过程占住）。
- **判断**：qwen3.8 为 27B 的 Q8 量化（权重约 30GB，加 KV cache 需 40GB+ 空闲内存），当前大概率是**服务器空闲内存不足或磁盘过慢**导致加载无法完成；客户端断开（curl 超时）后加载可能被取消/重启。
- **建议（按优先级）**：
  1. 在服务器网页端 Settings → API 开启 **Model auto-switch**（最省事，按需自动加载）；
  2. 检查服务器空闲内存（`free -h`）是否 ≥ 40GB，不足则关闭其他占用或加大内存/swap；
  3. 若内存确实不够，改用更小量化版本（如 Q4_K_M，约 16GB）并在 `config/llm_config.json` 同步更新 `model` id；
  4. 加载成功后再运行 `scripts/sceneB_llm_augment.py`（脚本带 mock 回退，模型未就绪时每条样本会等待 timeout 后回退，**不要在加载未完成时跑大 frac**）。
- **回退保障**：模型不可用时（无加载在途）chat 接口快速返回 400，`sceneB_llm_augment.py` 会逐样本秒级回退 mock 并打 `[llm失败回退: HTTPError]` 标记，管线不中断——2026-09-01 即以此方式产出了 15 维 schema 的 `features_augmented.csv`（来源标记为 mock，待模型就绪后重跑即可获得 LLM 真实判定）。

## 3. 全链路运行（双环境已跑通：.venv(P3.14) 与 .venv312(服务器同版本)）

```bash
cd 智能打标调研/04_方案设计与实施/sceneB
.venv312/bin/python scripts/sceneB_synth_data.py    # ① 合成 ODS 数据（纯stdlib，可跳过若已有）
.venv312/bin/python scripts/sceneB_featurize.py     # ② 特征宽表15维 + 自造标签 + 切分
.venv312/bin/python scripts/sceneB_llm_augment.py   # ③（可选）LLM 增强（2026-09-02 起真实可用）
.venv312/bin/python scripts/sceneB_model_router.py \
    --input output/features_augmented.csv           # ④ 训练+评估+全量打标（默认 xgboost；含 y_aug 列时优先用 LLM 校准标签）
# 路由参数：--model {xgboost,lr,rf,rule} 选方法；--compare 四方法同台对比；--mode predict 日常打标
#           --deploy <版本号> 显式上线（训练/对比只产新版本，不自动改 latest.json）
```

**2026-09-02 实测结果**（服务器同版本环境 `.venv312`，训练数据含 LLM 校准标签 y_aug；上线版本 `rf_20260902_121703`）：
初次训练 XGBoost **AUC=0.7697**（超 0.75 达标线）；四方法对比：**随机森林 0.7801** / RFM规则 0.7708 / XGBoost 0.7697 / 逻辑回归 0.7638（机器学习优于传统规则）；
LLM 与脚本标签一致率 65.2%（600 条 LLM 真实判定，frac=0.05）；全量打标分布：高危 22.5% / 中危 37.2% / 低危 40.3%；
Top 特征：`n_events_30d`(0.155) > `n_events` > `recency_days`（近30天行为是流失最强信号，符合业务直觉）。
对比基线 2026-09-01（Python 3.14，纯脚本标签未做 LLM 校准）：AUC=0.7134 —— LLM 业务校准在合成数据上带来约 +5.6 个百分点（数值不代表生产效果）。

## 4. 版本兼容说明（踩坑记录）

- **xgboost ≥ 2.0**：移除了 `use_label_encoder`；`early_stopping_rounds`/`eval_metric` 从 `fit()` 移到构造器。`sceneB_model_router.py` 已做**版本自适应**（用 `inspect` 探测参数位置），1.x 与 3.x 均可运行（服务器 3.0.5 与本机 3.4.1 均实测）。
- **scale_pos_weight 方向**：应为 负样本数/正样本数 = `(1-y.mean())/y.mean()`（上权重少数的流失类）；初版写成反了，已修正。
- pandas 2.3.2（服务器）/ 3.0.5（本机）、numpy 2.2.6（服务器）/ 2.5.2（本机）、scikit-learn 1.7.2（服务器）/ 1.9.0（本机）均与脚本兼容，`.venv312` 严格复测未发现问题。
